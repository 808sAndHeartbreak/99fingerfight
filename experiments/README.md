# 大师 AI 候选实验 · 2026-09-16

本目录是离线实验，不被游戏入口引用，不进入前端构建。正式 `src/ai-search.js` 保持不变，未部署。

## 基准与候选

基准固定为 Git 提交 `5365951` 的大师，双方使用当前规则 17 的同一引擎。有道具、99 HP、同样的抽取权重，不读取真实未来 RNG。

- 搜索版：己方候选宽度 18→24、操作深度 7→8；随机场景 2→3；对手回复预算 700→1500，并检查最多三条回复后取不利结果；后续反击预算 250→400。单场景主预算 16000→32000。保存于 `ai-master-candidate.js`。
- 评分版：不扩大搜索，只将有道具模式第二次归一的“潜在技能价值”从 25000 调整为 180。真实终局胜利仍为 100000。避免潜在机会在静态估值中压过生命和其他资源。由比较脚本基于固定基准生成。
- 无道具最终策略不改。先期扩大无道具深度的尝试，在标准开局重复陷入相同长对局；不同种子没有形成独立局面，因此不把这些结果当作强度证据。

## 方法

每个种子乘以 7919 初始化正式引擎，同一种子交换先后手。最大 500 条真实规则指令，超过只记“未决”，不宣称游戏平局。每一步都调用实际规则引擎，并自动验证指令合法性。这里的模拟不包含动画和真实倒计时。

先导样本用于初筛；后续种子未参与调整该候选。搜索版与评分版用了不同验证集，不能直接用两个百分比比较它们谁更强。两者均与同一基准比较。

耗时来自本机 Node.js，部分测试同时运行；平均值含必选动作，不能等同于手机浏览器耗时。先后手成对数据相关，少量领先不足以证明稳定提升。没有真人胜率数据，也没有训练模型。

## 复现

在仓库根目录运行：

```powershell
node scripts/compare-master.mjs 2001 8 holdout-a search
node scripts/compare-master.mjs 9001 8 holdout-b search
node scripts/compare-master.mjs 17001 8 holdout-b-score score
node scripts/compare-master.mjs 27001 16 holdout-b-confirm score
node --test tests/ai-master-candidate.test.js tests/ai-upgrade.test.js tests/match-options.test.js
```

脚本将基准与评分实验生成到被 Git 忽略的 `test-results`；逐局结果写入同目录 JSON。需要本地保留基准提交的 Git 历史。

24 项定向测试通过；额外检查了两种最终候选在 12 个人工无道具局面上与基准决策相同。斩杀、第二次归一、不依赖真实 RNG 的检查通过。

## 结果与结论

| 候选 | 初筛（不计入验证胜率） | 未参与调参的验证 | 验证胜率 |
|---|---|---|---|
| 搜索版 | 5 胜 3 负 | 19 胜 13 负（两批分别 8:8、11:5） | 59.4% |
| 评分版 | 4 胜 4 负 | 25 胜 23 负（两批分别 10:6、15:17） | 52.1% |

80 局验证全部在 500 操作以内结束。搜索版最慢约 1289 ms，基准在对应批次最慢约 482 ms；评分版最慢约 363 ms，基准约 378 ms。以上批次没有超过 2500 ms 的决策。搜索版各批平均耗时约为基准的 3～3.6 倍。

搜索版有小幅领先迹象，但跨批次波动较大、计算成本显著增加，尚不能断言稳定变强。评分版第二批 15:17，没有支持稳定增强的证据。两版均不替换正式大师，不发布。应优先收集具体败局中的漏斩杀和漏防守，再以关键局面回归驱动下一轮改进，而非继续盲目扩大搜索。

逐局结果、种子、先后手和耗时保存在 `master-results-2026-09-16.json`。无道具早期尝试和复现用的重复两局不计入上述 80 局。未在当前轮进行模型训练或任何线上修改。
